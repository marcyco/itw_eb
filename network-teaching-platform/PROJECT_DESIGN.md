# NetLab 深度网络协议交互平台 - 项目设计文档

## 📋 项目概述

### 项目名称
**NetLab** - 深度网络协议交互平台

### 项目定位
一款基于 macOS Sonoma 设计语言的网络协议可视化教学平台，通过交互式知识卡片和仿真实验，帮助用户深入理解网络协议的核心机制。

### 技术栈
- **前端**: React 18 + TypeScript + Ant Design 5
- **后端**: Python 3.8+ + FastAPI + SQLAlchemy
- **数据库**: MySQL 5.7+ / SQLite
- **实时通信**: WebSocket
- **状态管理**: Zustand / Redux Toolkit
- **动画库**: Framer Motion + React Spring

## 🎨 全局设计规范

### 视觉风格
- **设计语言**: 严格遵循 macOS Sonoma 设计语言
- **毛玻璃效果**: `backdrop-filter: blur(20px)` + 高透明度背景
- **背景**: 深灰渐变 (`linear-gradient(135deg, #1a1a2e 0%, #16213e 100%)`)
- **卡片边框**: 圆角 12px，阴影 `box-shadow: 0 4px 20px rgba(0,0,0,0.1)`
- **按钮**: 圆角胶囊 `border-radius: 20px`，hover 时 `transform: scale(1.05)`
- **动画**: 所有过渡 `transition: all 0.3s ease`

### 交互逻辑

1. **知识卡片**: 支持左右滑动翻页，底部小圆点指示器
2. **进入实验**: 滑到最后一张卡片时，出现"进入实验"按钮（呼吸灯效果）
3. **实验加载**: 点击后卡片向上飞出，加载模板实验画布
4. **OSI 面板**: 点击数据包/设备时从右侧滑出，展示对应层级详细数据

## 📚 功能模块设计

### 1. TCP 协议学习页

#### 阶段 1: 知识卡片（滑动式）

| 卡片 | 标题 | 内容 |
|------|------|------|
| 卡片 1 | TCP 连接管理：三次握手 | 状态变迁图（Client→SYN→Server→SYN-ACK→Client→ACK），配文字说明 |
| 卡片 2 | 可靠传输：滑动窗口机制 | 图解 Seq、Ack、Window Size 的关系，展示数据包批量发送动画 |
| 卡片 3 | 流量控制：拥塞避免与快速重传 | 慢启动/拥塞避免曲线图，说明 RTO 触发条件 |

#### 阶段 2: 模板实验

**拓扑**: 客户端主机 ↔ 服务器（已连线）

**交互面板参数**:
- 发送窗口大小（默认：3）
- 是否模拟丢包（开关）
- 拥塞控制算法（Reno/Cubic/BBR）

**数据可视化**:
- 连线上显示带 Seq 号的数据包
- 模拟丢包时，数据包变红，触发快速重传

**OSI 面板展示**:
- TCP 段结构：Src Port, Dst Port, Seq, Ack, Flags, Window Size
- 十六进制/二进制数据呈现

---

### 2. UDP 协议学习页

#### 阶段 1: 知识卡片（滑动式）

| 卡片 | 标题 | 内容 |
|------|------|------|
| 卡片 1 | UDP：无连接的快速传输 | 对比 TCP，展示 UDP 头部（端口、长度、校验和） |
| 卡片 2 | 数据分片：MTU 的限制 | 图解 IP 层分片，说明重组过程 |
| 卡片 3 | UDP 的应用：实时通信 | DNS、视频流、在线游戏等场景 |

#### 阶段 2: 模板实验

**拓扑**: 主机 A ↔ 主机 B ↔ 主机 C（广播场景）

**交互面板参数**:
- 数据包大小（默认：1500B）
- 是否模拟丢包（开关）

**数据可视化**:
- 数据包瞬间到达（无确认过程）
- 超过 MTU 时显示分片动画（Fragment Offset）
- 丢包时提示"数据不完整，无法重组"

**OSI 面板展示**:
- UDP 报文结构：Src Port, Dst Port, Length
- IP 分片结构：ID, Fragment Offset, MF 位

### 3. HTTP 协议学习页

#### 阶段 1: 知识卡片（滑动式）

| 卡片 | 标题 | 内容 |
|------|------|------|

**交互面板**:

**数据可视化**:
- 请求包（蓝色）和响应包（绿色）
- 404 状态码提示
- HTTPS 时展示 TLS 握手动画

**OSI 面板展示**:
- HTTP 报文格式：请求行、首部行、实体主体
- TLS 加密数据（若为 HTTPS）

### 4. RIP 路由协议页

#### 阶段 1: 知识卡片（滑动式）

| 卡片 | 标题 | 内容 |
|------|------|------|
| 卡片 1 | RIP：距离矢量路由协议 | 跳数（Hop Count）作为度量值，最大跳数 15 |
| 卡片 2 | 路由更新：动态收敛 | 路由器间交换 RIP 更新包（UDP 520 端口） |
| 卡片 3 | 环路避免：水平分割与毒性逆转 | 防止环路的机制说明 |

#### 阶段 2: 模板实验

**拓扑**: R1 ↔ R2 ↔ R3（不同网段）

**交互面板**:
- 发送更新（触发 RIP 广播）
- 断开链路（模拟故障）
- 重置拓扑

**数据可视化**:
- RIP 报文（橙色波纹）在路由器间传播
- 路由表悬浮窗实时更新
- 断开链路时标记"16（不可达）"

**OSI 面板展示**:
- RIP 报文结构：Command, Version, Route Entry（IP, Mask, Metric）

### 5. FTP 协议学习页

#### 阶段 1: 知识卡片（滑动式）

| 卡片 | 标题 | 内容 |
|------|------|------|
| 卡片 1 | FTP：控制连接（21）与数据连接（20） | 控制连接传输命令，数据连接传输文件 |
| 卡片 2 | FTP 模式：主动 vs 被动 | 两种模式的流程对比 |
| 卡片 3 | FTP 命令与响应码 | USER, PASS, RETR, STOR 等命令及响应码 |

#### 阶段 2: 模板实验

**拓扑**: 客户端 ↔ 服务器（两条连线：控制连接细线、数据连接粗线）

**交互面板**:
- 模式选择（主动/被动）
- 用户名/密码输入
- 文件选择（如 test.txt）

**数据可视化**:
- 控制连接显示命令流（细线，文本格式）
- 数据连接显示文件流动画（粗线，带进度条）

**OSI 面板展示**:
- FTP 命令格式（如 USER admin）
- 文件数据流

### 6. 综合自由实验室

#### 阶段 1: 知识卡片（滑动式）

| 卡片 | 标题 | 内容 |
|------|------|------|
| 卡片 1 | 自由实验室：构建拓扑 | 设备拖拽、手动连线规则 |
| 卡片 2 | 配置网络参数 | IP 地址、子网掩码、默认网关配置 |

#### 阶段 2: 模板实验

**设备库**: 主机、路由器、交换机、云

**交互**:
- 拖拽设备并手动连线（端口级）
- 配置 IP、子网掩码、网关
- ping 命令模拟跨网段通信
- 支持模拟丢包

**分析面板**:
- ICMP Request→IP→Ethernet 封装过程
- TCP 的 Seq/Ack 分析
